# Troubleshooting
프로젝트 진행 중 발생한 트러블과 에러, 해결 과정을 기록하기 위한 디렉토리입니다.

## 작성 방법 (문서 템플릿)
개별 트러블슈팅 문서(md 파일)를 작성할 때는 다음 목차로 작성합니다..

1. **문제 현상 (Symptom):** 어떤 상황에서 어떤 에러가 발생했는지 (에러 로그 첨부)
2. **원인 추론 (Cause):** 왜 이런 문제가 발생했는지에 대한 고민과 분석
3. **해결 방법 (Solution):** 시도한 방법과 최종적으로 문제를 해결한 방법
4. **배운 점 (Lesson Learned):** 이 문제를 통해 새롭게 알게 된 CS 지식이나 프레임워크의 원리

## 주의사항
- 파일의 제목(파일명)은 직관적이고 간단하게 만든다. (예: `01_cors_error.md`, `02_db_connection.md`)
- 에러 로그나 코드는 마크다운 코드 블록(```)을 사용하여 가독성 있게 첨부한다.
- 구글링이나 AI를 통해 찾은 답을 그대로 복사하기보다, 본인이 이해한 언어로 풀어서 원인을 기록한다.
- 각 문제의 간단한 설명과 링크를 현 README 파일의 '트러블슈팅 목록'에 반드시 업데이트한다.
